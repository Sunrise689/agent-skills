## 示例：技术分析大师（微信小程序）交接文档

- 微信小程序 AppID：`wxb3d6fd4edafe74cf`
- CloudBase 环境：`cloud1-d5gt0lb2xcd72babe`
- 本地项目：
  - Python/FAE 项目根目录：`[本机]\Documents\kline-pattern-master`
  - 微信小程序实际目录：`[本机]\WeChatProjects\miniprogram-1`
  - 后端目录：`...\wechat-miniprogram\backend`
  - 形态核心库：`...\scripts\pattern_core_v7.py`
  - FAE 判断层：`...\fae\judgment`
- **写法要点**：目录路径写全，每个文件配一句话说明。接手者打开路径就能对上号。

### 2. 初始目标与原始需求

- 一开始想做的是：技术分析大师小程序，把"月线定方向、周线看力度、日线找位置"的三周期分析方法做成工具，让用户不用翻几十个指标页面就能得到结构化的技术分析结论。
- 核心原则：大级别趋势压制小级别信号；前端的"买/卖"文字只表示参考位置，不能写成确定的交易指令。
- **写法要点**：一句话说清"为什么做这个"，防止接手者只盯着当前卡点忘了大方向。

### 3. 工具栈与环境

- 后端：FastAPI（`backend/app.py`），会把项目根目录下 `scripts` 放入 Python 路径，调用 `kline_pattern_report.py`、`pattern_core_v7.py` 和 FAE 判断层。**因此部署包必须保留这两个脚本以及 `fae` 运行时源代码和数据。**
- 前端：微信小程序原生，关键页面/组件见 `services/analysis.js`、`components/kline-chart`、`data/knowledge.js`。
- 部署：CloudBase 托管，代码包上传后 Docker 构建。
- 远程 DouyinSans 字体曾被 Gitee 的 CORS 拦截；**不要依赖远程字体 URL**，使用系统字体或项目内字体回退即可。
- **写法要点**：工具不只要列名字，要写"谁依赖谁、缺失会导致什么、有什么坑"。

### 4. 数据与数据库

- 数据来源：行情接口（真实行情调用验证阶段）。
- FAE 注册表：`fae\judgment\pattern_registry.py` 与 `pattern_registry.json`——FAE 判断依赖的核心数据。
- 知识提示与反馈记录：`frontend_pattern_knowledge_prompt.md`、`frontend_to_backend_feedback.md`。
- **写法要点**：写清核心数据文件在哪、是干什么的、动了会有什么后果。

### 6. 已知问题与坑（重点展开）

**部署错误的真实原因（最痛的坑单独写）：**

日志：`[本机]\Downloads\technical-analysis-api-005-log.txt`

关键错误：
```text
grpc: failed to unmarshal the received message: string field contains invalid UTF-8
ERROR: failed to solve: Internal: rpc error ... invalid UTF-8
```

这不是 Python 依赖、端口或 Dockerfile 的错误。005 包把生成物和损坏的中文文件名一起放进了 Docker build context（如 `scripts/SH000001_K锟斤拷...pdf`）。这些文件在 CloudBase 解压时已出现替换字符，Docker 发送构建上下文时无法把路径序列化为合法 UTF-8，所以在执行 `pip install` 之前就失败。

**修复方式**：v6 只排除运行时不会被导入的生成物（PDF、PNG、缓存、日志、损坏文件名文档），保留全部业务功能。**不要再上传 v4/v5。**

- **写法要点**：坑要写"现象+根因+修复方式+别再犯"四个要素。最痛的坑单独一节详细写，不跟小问题混在一起。

### 7. 下一步计划（接手后先做什么）

部署优先：
1. 上传 v6 包到 CloudBase（步骤：控制台→服务管理→更新本地代码→上传→目标目录 `.`→端口保持80）
2. 确认构建成功，记录新版本号和启动日志
3. 通过真实行情调用四个接口（图表分析/均线无忧/指标大师/缠中说禅）

后续产品开发：
- FAE：继续增加标准案例、相似度、候选优先级、硬冲突消解
- 前端：补教学内容、减少形态标注拥挤
- AI 报告：接入 API，AI 只负责自然语言组织

- **写法要点**：先写"马上要做的"，再写"后面要做的"，分优先级。部署/执行步骤写到可直接照做。

### 8. 约束与偏好（红线）

- 不制作删除功能的精简包，不回退到旧前端或旧后端。
- 未经明确证据，不改 `pattern_core_v7.py` 的核心检测逻辑。
- 每次改动后至少运行 Python 编译、Node 语法检查和必要接口测试。
- 不把 API Key 写入前端、日志、ZIP 或交接文档。
- FAE 只负责客观形态判断，不负责趋势命名、市场状态主观命名或操作建议。
- 反转形态必须结合位置和后续确认；买/卖标签是参考位置，不是保证盈利的指令。

- **写法要点**：红线写清楚，接手者不敢乱动的东西都要列出来。

## 提炼出的核心方法论

1. **路径写全**：每个文件/目录配一句话说明用途。
2. **坑单列详写**：最痛的坑值得一整节，四要素=现象+根因+修复+别再犯。
3. **版本/方案说死**："用v6不用v4/v5，因为xxx"——不给接手者选择困难。
4. **步骤可照做**：部署步骤写到点几下鼠标的程度。
5. **红线单独列**：不能碰的边界集中在一起，接手者一眼扫完。
6. **开场白给好**：连"新对话第一句话说什么"都写好了。
7. **决策带原因**：每个"不做什么"都解释为什么，防止接手者推翻。
