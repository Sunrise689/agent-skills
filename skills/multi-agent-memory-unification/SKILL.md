# 多 Agent 记忆统一

## 何时使用
- 触发词：多平台记忆同步、几个 Agent 知识不一致、换工具忘事、重复沉淀、记忆合并、正本、MEMORY.md。
- 适用：两套及以上 AI 工具并存（本地编程 Agent、桌面助手、云端智能体等），需要一份共同承认的事实库。
- 不适用：单工具内部的记忆整理；涉密凭据的托管（见红线）。
- 前置条件：已确定唯一正本库的本地落盘位置（建议纳入版本管理）；各平台能读到正本目录，或至少能导出自身记忆。

## 任务目标
核心原则：**一个正本，多种工具**。把分散在各平台的记忆收敛为一份正本库（MEMORY.md 索引 + 分类子目录）：来源可追溯、结论分层、启动协议统一；此后新增记忆只写正本，各平台只提交原材料。

## 操作步骤（五步）
1. **盘点**：先读正本 MEMORY.md，再逐平台盘点记忆入口、索引、摘要、raw 来源和散落的临时笔记，列成清单（平台名 / 入口路径 / 记忆形式 / 数量）。
2. **原始材料完整归档**：把各平台原始记忆原样放入正本库 `sources/<平台名>/`，一个字不改。来源只是来源，不冒充权威结论。
3. **结论归并分层**：把可复用结论归并进分层目录——`experiences/`（踩坑与修复实录）、`methods/`（可复用方法）、`philosophy/`（原则与偏好）。合并重复内容时保留**真实完成状态**（做没做成、验证没验证，不美化）。
4. **改启动协议**：把每个平台的启动协议/系统提示改成“先读正本、平台本地不另立知识”；平台自动记忆目录只保留镜像职责，不再作为知识源。
5. **验收与立规矩**：按四个口径验收——文件清单（计划归档 vs 实际归档）、来源数量（各平台原材料是否齐全）、关键索引（MEMORY.md 能否检索到新归并条目）、内容差异（正本与各平台副本 diff 只剩预期差异）。验收通过后宣布规矩：新增记忆只写正本。

## 坑与红线
- 来源文件 ≠ 权威记忆：`sources/` 里的内容永远只是证据，结论必须重新归并才能进 experiences/methods。
- 凭据、令牌、账号类内容不进正本库明文：只登记“存在哪、如何索取”；这类同步必须由用户本人/主会话亲自执行，不派子智能体。
- 聊天记录只提炼压缩后放精华，不搬全量流水。
- 云端/平台专属能力（如只有云端能发邮件），本地只留一行说明，不搬实现细节。
- 合并冲突以“带验证证据的一方”为准；拿不准就两边都保留并标注待验证。
- 同步方向固定“边缘 → 正本”，禁止反向用平台私有记忆覆盖正本。

## 验证方式
- 抽查 5 条旧记忆：在正本中能找到，且能溯源到 `sources/` 原始材料。
- 各平台冷启动后复述关键事实，与正本一致。
- diff 检查：正本之外不再有“只有某平台知道”的独有结论；四个验收口径逐项过一遍。
