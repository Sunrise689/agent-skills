# 深度搜索（Deep Search）

## 任务目标
本 Skill 是主流 AI 平台"深度搜索/Deep Research"功能的平替方案：不依赖平台专有深度搜索能力，通过多探针联网搜索 + 信息原子提纯，自己完成深度研究。
- **速度目标**：简单问题 ≤1 分钟，中等问题 2~3 分钟，困难问题 ≤5 分钟（坚决不出现 ChatGPT 那种动辄十几分钟的情况）
- **质量目标**：信息覆盖全面、来源可靠、结构清晰，能在速度与全面性之间取得平衡
- **唯一触发词**："深度搜索"或"deep search"——用户没说这两个词时，不触发本 Skill，走常规搜索

## 使用规则
- 统一标准版流程，不再区分"精简版/详细版""还原版/信息搜集版"
- 探针数量与字数按问题复杂度自适应：
  - **简单**（单点事实型，如"XX 是什么""XX 最新版本"）：探针 3~5 个，字数 ≤1000
  - **中等**（有前因后果或需多视角，大部分日常深度问题）：探针 5~6 个（标准），字数 1000~5000，目标 2~3 分钟出结果
  - **困难及以上**（系统性、强争议、需深挖的问题）：探针 7+ 个且强化原子提纯，字数 5000~10000（上限 1 万），目标 ≤5 分钟
- **默认倾向**：简单/中等问题尽量精简，不要为了"全面"而过度展开
- **速度优先原则**：遇到平台卡慢、网页 403/登录墙时不反复重试，标注"该平台一手数据未获取"后继续下一探针
- **不使用云手机**，不依赖任何平台专有插件，所有采集只走"联网搜索（search_web）+ 网页读取（fetch_web）"

## 操作步骤
按以下顺序自动执行，过程不向用户展示（探针清单与内部推理不输出），直接出最终报告：

### 第 0 步：复杂度识别（≤10 秒）
- 快速判断问题属于简单 / 中等 / 困难
- 若识别为**困难及以上** → 先询问用户：「这个问题比较复杂，完整深度研究可能耗时较久（5000 字以上，约 5 分钟）。是否仍深度研究？还是用快速模式（1000~5000 字、2~3 分钟，但相对没那么全面）？」
  - 用户选快速模式 → 降为中等档
  - 用户确认深度研究 → 按困难档执行
- **简单/中等问题不询问，直接执行**

### 第 1 步：混沌采样（≤30 秒）
- 基于已有知识做一次基础扫描，快速在脑内勾勒：核心人物/组织、关键事件、时间线、主要争议、关键数据
- 这一步不输出给用户，只作为后续提纯的地基
- 如果话题完全陌生，可先用 1 次宽泛 search_web 做真实采样（不展开，只看搜索结果标题/snippet 建立轮廓）

### 第 2 步：实体识别
列出"检索原子"——可直接用于搜索的具体实体：
- 人物（核心当事人）
- 组织（公司、机构、品牌）
- 事件（具体冲突、变化、产品、版本）
- 时间（关键日期/版本号/里程碑）
- 数字（有信息量的具体数字）
- 其他可检索名词

### 第 3 步：意义原子提纯（关键质量环节）
基于混沌信息与实体，提炼出 N 个"意义原子"——即 N 个**独立、低互信息（高正交纯度）**的观察视角，每个原子对应若干检索实体。
- **正交纯度原则**：原子之间互信息要低，不要"经济角度/金融角度"这种高度重叠的假独立；一个原子要像基本色（红/黄/蓝），而不是已经调好的"橙红色"
- **收敛原则**：所有原子都要能被核心话题"收住"，无法收拢的原子视为噪声剔除
- 原子数量 = 探针数量（简单 3~5、中等 5~6、困难 7+）

### 第 4 步：生成探针清单
以核心话题为锚点，生成一组"组合探针"。每个探针包含：
- **搜索指令**（由检索原子组合而成，2~4 个关键词，不要一句话）
- **观察点**（阅读时重点关注什么，避免读后无重点）
- **对应意义原子**（该探针服务于哪个视角）

探针按优先级排列：从最核心到最外围。**前 3 个探针必须是核心争议/核心事实/核心人物，外围补充探针可以并行。**

### 第 5 步：探针执行（主力耗时环节）
- 依次执行每个探针的 search_web，按观察点提炼关键信息
- 关键来源（官网、财报、权威媒体、论文）用 fetch_web 读取原文
- 每个探针聚焦近 1~2 年的信息；历史背景类问题再扩展时间范围
- **速度优化**：
  - 简单问题：可以在一个 search_web 的 query_list 里并行放 3~5 个关键词批量搜
  - 中等问题：核心探针（前 3 个）逐次精读，外围探针可以批量搜
  - 困难问题：核心探针逐次精读 + fetch_web，外围探针批量
- 遇到 fetch_web 失败（403/登录/空页），不重试、不把 URL 当关键词回搜，直接标注"一手页面未获取，以下为二手信息"
- 小红书/抖音/微博等 UGC 内容：通过公开 web 搜索覆盖，拿不到一手数据时注明
- 微信公众号文章：通过公开 web 搜索定位后 fetch_web 正文

### 第 6 步：结果处理（收敛输出）
按问题性质自动选择展开方式，**输出骨架统一但不显式标注结构名称**（不要出现"开头总结""中间分段""结尾"这类标题）：
1. **开头（总括总结）**：第一段话点明核心结论/全貌，让读者 10 秒内知道答案。不写"开头总结"四个字。
2. **中间（分段展开）**：
   - **来龙去脉/还原类**（用户想弄清事件脉络，如某商业事件因果、某明星事件）→ 按时间线或因果链串起来龙去脉，突出转折点、矛盾点（"裂开的纹路"）、各方视角的张力。用自然段落衔接，每段一个角度或一个阶段
   - **信息搜集类**（用户要的是多角度资料汇总、产品对比、行业盘点）→ 按主题分段，每段聚焦一个独立信息点/视角/数据/案例，不强行整合成单一结论。段落小标题可用简洁描述性短语（如"市场全景""产品定位"），不要叫"第一段""角度一"
3. **结尾（收束）**：最后 1~2 段收束总结 + 可补充"可能遗漏的视角"或下一步建议。不写"结尾"两个字。

**文件生成规则**：
- **简单档**：默认不生成文件，直接在对话里自然语言输出（杀鸡不用牛刀）
- **中等/困难档**：**默认自动生成排版精美的 HTML 工作底稿**，不询问用户（这是默认行为，用户无需每次要求）。仅在环境不允许生成文件时，退化为对话直接输出并说明原因
- HTML 底稿规范：
  - **生成 HTML 前先阅读 `references/report-template.html` 作为结构参考，按模板骨架填充实际内容（将 `{{占位符}}` 替换为真实内容），不要每次凭空发挥**
  - 单文件自包含，CSS 内联，无外链，浏览器直接打开可读
  - 标题层级清晰、重点加粗、关键数据高亮
  - 结构合适时加入 Mermaid 思维导图/流程图（如研究框架、因果链、对比关系）；纯叙述型报告可删除模板中的思维导图区
  - 来源标注用 `<a>` 元素链接到 URL（`target="_blank" rel="noopener noreferrer"`），来源名称为链接可见文字，不用笼统的"来源/参考"标签
  - 风格参考 create-html-artifact 技能的质量标准（生成 HTML 前应加载并使用该技能）
- 输出后告知用户文档路径

## 输出格式要求
- **过程全部隐藏**：混沌采样、实体识别、原子提纯、探针清单都不展示给用户，直接出最终报告
- **默认输出**：简单档对话直接输出；中等/困难档默认生成 HTML 工作底稿（见文件生成规则），同时在对话里给一段精简摘要（核心结论+文档路径）
- **不用表格**（除非用户明确要）：用自然段落呈现，避免大段分点列表
- **结构标签不外露**：不要出现"开头总结""中间分段""结尾"等结构说明文字；段落小标题用内容本身的描述（如"市场全景""技术路线"），不要用编号或角度命名
- **来源标注**：关键结论、关键数据附近用 `[来源名称](url)` 内联标注；同一来源不重复标
- **字数严格控制**：简单 ≤1000、中等 1000~5000、困难 5000~10000；不凑字数、不水
- **直奔主题**：不要"下面为您整理""经过深度搜索"这类废话开场
- **默认不生成文件**：直接对话输出，不主动存文件；仅困难档且超 5000 字时询问是否保存

## 信息源使用原则
- 权威性优先：官网/财报/法规原文 > 权威媒体/机构报告 > 行业自媒体 > UGC/论坛
- 交叉验证：核心事实必须 ≥2 个独立来源印证；只有单一来源的注明"据 XX 报道，暂未交叉验证"
- 时效性：优先近 1~2 年；历史回溯类问题按时间需要扩展
- 平衡中立：不预先偏向任何平台或信源
