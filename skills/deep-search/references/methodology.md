# 深度搜索方法论详解（Deep Search）

> 本文件是 [SKILL.md](../SKILL.md) 的参考补充，用于执行者在需要理解"意义原子提纯""探针组合""正交纯度"等概念细节时查阅；标准执行流程以 SKILL.md 为准。

## 一、核心概念：信息原子

深度搜索的本质不是"多搜几次"，而是**先拆分视角，再按视角有目的地搜**。这里的视角单元叫做"意义原子"（或"信息原子"）。

### 1.1 什么是好的原子
一个好的意义原子满足三个条件：
- **独立可命名**：用 2~8 个字就能命名，有质感、可想象，不是空泛大词（比如"经济角度"太大，要拆成"成本结构""定价策略""供应链"这种具体维度）
- **高正交纯度（低互信息）**：原子之间互信息要低。"经济角度"和"金融角度"互信息太高（金融是经济子集），不能并列；"成本结构"和"用户情绪"互信息低，是好的并列
- **可收敛**：每个原子都必须能被核心话题收住。搜"奶茶店竞争力"时，"量子纠缠"只有能具体落到"用户体验设计"上才算有效原子，否则是噪声

> 类比：高纯度原子就像三原色（红/黄/蓝），能调出任何颜色；低纯度原子就像已经调好的"橙红色"，能用的场景很窄。

### 1.2 原子数量与复杂度的关系
| 复杂度 | 原子数量 | 每个原子纯度要求 | 典型场景 |
|---|---|---|---|
| 简单 | 3~5 个 | 允许部分重叠，以快为主 | "XX 是什么产品" |
| 中等 | 5~6 个 | 前 3 个必须正交，后 2~3 个可做补充 | 行业盘点、事件脉络 |
| 困难 | 7+ 个 | 所有原子严格正交，避免假独立 | 系统性研究、争议事件还原 |

## 二、探针生成技巧

### 2.1 搜索指令的写法
- **关键词组合**，不要一句话：`Cursor + 定价 + 2026` 比 `Cursor 在 2026 年的定价是多少` 搜出来的结果更全
- **2~4 个关键词**最佳，超过 4 个会被搜索引擎收窄到几乎没结果
- **用英文搜全球产品**：对海外产品（Cursor、Claude Code），混合英文关键词效果显著更好
- **时间限定可放 freshness 参数**，不要硬塞进关键词

### 2.2 观察点的作用
观察点是探针的"阅读眼睛"。没有观察点的探针容易搜完一堆内容但提炼不出东西。好的观察点：
- 具体：不是"了解相关信息"，而是"Cursor 的 2026 年定价档位、Pro/Business/Enterprise 的区别、有没有涨价"
- 聚焦：一个观察点聚焦一个问题，不要一次观察 5 件事
- 服务于意义原子：每个探针的观察点应该直接回答它所对应原子的核心疑问

### 2.3 探针优先级
- **前 3 个探针 = 骨架**：必须覆盖核心事件/核心人物/核心争议，这三个探针质量决定整体报告质量
- **中间 2~3 个探针 = 血肉**：补充次要视角、数据、案例
- **最后 1~2 个探针 = 边角**：反方观点、小众视角、可能遗漏的维度

## 三、结果整合：两种展开方式

虽然输出骨架都是"开头总结 + 中间分段 + 结尾收束"，但中间段的组织方式根据问题性质自动选择：

### 3.1 来龙去脉/还原类（因果链结构）
适用：用户想弄清"这件事到底怎么回事"——某明星绯闻、某商业事件因果、某公司兴衰。

中间段按时间线或因果链组织：
- 背景铺陈（前置条件）
- 导火索/引爆点
- 关键转折（"裂开的纹路"——事情在哪个节点不可逆转）
- 各方反应（当事人/对手/公众/监管）
- 当前状态/结果

关键：找出**最深层的矛盾或转折点**，不要按时间机械罗列，要突出"为什么会这样"。

### 3.2 信息搜集/盘点类（主题分类结构）
适用：用户要的是资料汇总——产品对比、行业盘点、方法论整理、政策汇总。

中间段按主题分类组织：
- 每个主题一个独立小节
- 小节内用自然段落陈述事实/数据/案例
- 不强行把所有信息拼成一个"大故事"

关键：**信息点独立、注明来源、不强行整合**。遇到矛盾信息时并列呈现（"A 媒体报道 X，B 媒体报道 Y，暂未交叉验证"），不要替用户拍板。

## 四、速度优化经验

- **并行批量搜索**：简单问题可以把 3~5 个关键词放进 search_web 的 query_list 一次性批量搜，节省多轮 RTT
- **核心精读、外围粗读**：前 3 个关键探针必要时 fetch_web 读原文，外围探针直接看 search_web snippet 即可
- **不重试失败页面**：fetch_web 失败（403/登录/空页/超时）→ 标注"该来源一手页面未获取"→ 继续下一探针，绝不把 URL 当关键词再去搜索引擎回搜
- **不展开无关方向**：搜索过程中看到的"有趣但不服务于任何意义原子"的信息，果断丢弃
- **字数硬约束**：简单 ≤1000、中等 1000~5000、困难 5000~10000，写完后如果超字数必须砍

## 五、常见反模式（务必避免）

1. **假独立原子**：列 5 个原子但本质只讲了 2 件事（比如"产品功能""产品特性""产品特点"是同一个原子）
2. **跑题发散**：搜到一个有趣的边角料就展开一大段，忘了核心话题
3. **版本/目标问用户**：不再让用户选版本或目标，由复杂度识别自动决定
4. **云手机/专有插件依赖**：主对话环境没有这些，依赖它们必然失败
5. **过程外显**：把探针清单、混沌采样、实体识别过程展示给用户，增加阅读负担
6. **过度展开简单题**：用户问"XX 是什么"，不需要给 5000 字综述
7. **重复标注同一来源**：同一节里来自同一来源的信息只标一次
8. **强整合信息搜集题**：用户要盘点时，不要硬编一个"大结论"

## 六、完整示例（中等·信息搜集类）

**话题**：2026 年 AI 编程助手（Cursor/Claude Code/Codex/Gemini CLI）竞争格局

**原子清单（5~6 个）**：
1. 产品定位与核心差异（每个产品主打什么）
2. 定价策略与商业模式对比
3. 技术能力对比（代码补全/Agent 能力/上下文窗口）
4. 用户规模与市场份额
5. 2026 年重大更新/融资/商业化动作
6. 开发者生态与口碑争议

**探针（核心 3 个精读 + 外围批量）**：
- 探针 1（核心）：`AI coding assistant 2026 market landscape Cursor Claude Code` → 观察点：整体格局报告、各家最新定位
- 探针 2（核心）：`Cursor pricing 2026` / `Claude Code pricing` / `Codex CLI pricing` → 观察点：各家定价档位对比
- 探针 3（核心）：`Cursor vs Claude Code vs Codex comparison 2026` → 观察点：横向评测、能力差异
- 探针 4（外围，批量）：`AI coding assistant market share 2026` + `Cursor users 2026` → 观察点：用户规模数据
- 探针 5（外围，批量）：`AI coding assistant controversy 2026` + `Cursor privacy concern` → 观察点：争议/口碑问题

**输出骨架**：开头总结（一句话格局判断）→ 中间按 6 个原子分段 → 结尾（趋势判断 + 可能遗漏的视角如开源替代品）。
