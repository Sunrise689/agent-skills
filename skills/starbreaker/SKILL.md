# Starbreaker：手游资源包定向解包方法论

## 何时使用
- 触发词：资源包解包、数值表提取、VFS 包分析、定向提取配置表。
- 适用：资源按“虚拟路径哈希索引 + 分块压缩”组织的本地打包格式。
- 不适用：在线服务端数据、他人设备上的内容、任何以分发为目的的提取、未购内容。
- 前置条件与合规边界：仅限**自有设备、已购内容、个人研究**，不含任何形式分发；仅本地静态分析，不登录、不 root、不注入、不读运行时内存；本地具备脚本环境与十六进制查看工具。整个过程依赖大量实测和比对，不存在一键配方。

## 任务目标
在不发起网络请求、不改动客户端的前提下，从本地资源包中定向定位并解码目标数值配置表，且全程只沉淀“方法论”，不沉淀“配方”。

## 操作步骤（四层链路）
1. **路径哈希层**：包内不存明文路径，虚拟路径被映射为确定性哈希（常见为正向 + 反向双通道叠加的 64 位变体）。做法：用少量已知路径样本实测校准哈希结构，再以双向变体批量构造候选路径字典，到包内反查哈希命中。要找新表时，从元数据的字符串字面量挖表名，拼出路径候选再哈希搜索。
2. **分块定位层**：目标内容被切成多个块，块尾带“哈希 + 块号”trailer。做法：先扫 trailer 拿到（主块号，子块号）索引，再从 trailer 向前扫描块头——块头自带自身偏移、跨度、压缩类型、原始长度等自校验字段，满足自校验条件的才是真块头。校验是自我证明的，不靠猜。
3. **解压还原层**：分块是**无加密的块压缩**，按块号排序逐一解压、顺序拼接即得原始文件。关键认知：“有加密”常常只是假设——代码里名字带加密字样的方法未必用在资源包上，先实测验证（解压能否成功、校验能否对上），证伪前不要放弃无加密路线。
4. **记录解析层**：数值表多为固定长记录表：文件头存版本/大小/校验等元信息，随后 N 条等长记录，字符串区在记录区之后。字段语义从元数据里的类定义（字段名与偏移）反推：固定长条目大小 × 字段偏移 = 任意字段的数值位置。

## 通用经验（跨项目可复用）
- **引擎升级改布局**：同一引擎不同版本的结构体/条目字节数不同，且可能被厂商魔改成非标准值；换版本必须实测重新校准条目长度，切勿照搬旧参数。
- **新版数据在热更包**：基础包内嵌的是旧版数据，当前版本数值在热更补丁里；对热更包沿同一链路再走一遍即可，方法完全通用。
- **存储可见性差异**：外部存储的公共目录通常可直接读取；应用私有内部存储默认对调试通道不可见——外部往往只有缓存和日志，主体热更资源在内部。
- **命令行路径坑**：Git Bash 下以 / 开头的远程路径会被 MSYS 强制转成本地路径（如 /sdcard 被映射成本地盘符路径），用 adb 拉文件前须禁用路径转换（`export MSYS_NO_PATHCONV=1`）。
- **格式家族化**：同一厂商的打包器在安装包与运行时缓存里往往是同族格式（版本号递增），解析思路可平移，只是头结构版本不同。

## 坑与红线
- 严禁把任何实测出的常量、偏移、脚本当作“配方”记录或外传；本文档本身即为口径范本——只讲思路，不含哈希常量真值、魔法数字配方、脚本代码、可复现参数、游戏/公司/包名。
- 对外语术口径固定为：基于大量实测和比对的逆向分析方法，仅限自有设备上对已购内容做个人研究，不含分发。
- 不碰在线服务端数据、不抓运行时内存、不做任何对抗检测或规避风控的改动。
- 字段倍率（原始值→面板值换算）必须有实测对照才可采信；标注 candidate 的换算不得当作结论。

## 验证方式
- 哈希层：已知路径样本全部命中，构造字典后能在包内搜到对应条目。
- 分块层：每块自校验条件全部通过，拼接后文件头元信息（版本/大小/校验值）自洽。
- 解析层：抽取若干条记录与实际面板值比对，误差为 0 才算解通。
- 全链路：换一张新表，不依赖旧参数独立走通一遍，才证明方法而非记忆。
