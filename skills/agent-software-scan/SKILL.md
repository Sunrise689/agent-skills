# Agent 软件功能扫描

## 何时使用

- 触发词："研究下这个新 agent/编码软件""它能不能接进工具箱""做一次功能扫描""评估某某平台"。
- 适用：任何新出现的智能体客户端、编码助手、自动化平台，在接入前或选型时的尽调。
- 不适用：已深度使用的工具的日常调优；纯界面外观评测。
- 前置条件：能实际安装运行，或至少以公开文档+社区反馈做只读评估（后者所有结论必须标注"未经实测"）。目标软件无法本地运行且无公开资料时，输出"信息缺口清单"而非结论。

## 任务目标

产出一份四层全覆盖的扫描报告 + 一条适配性结论：它适合干什么活、与现有工具箱如何互补（轻装干快活/重装啃硬活的定位）、接入成本与风险。四层缺任何一层即视为扫描未完成。

## 操作步骤

1. **建立底档**：名称、版本、运行形态（本地/云端/混合）、公开定价与额度规则（只记公开信息，不录入任何凭证）、安装与卸载成本。
2. **第一层——loop 循环机制**：单轮对话还是自主循环？循环上限、工具调用深度、能否多步自主推进、失败重试与中止方式。判断它能"自己走多远"。
3. **第二层——harness 调度与上下文组装**：上下文如何组装（系统提示、历史、工具结果的拼接顺序）、裁剪与压缩策略、并行任务与子代理能力、权限与沙箱模型。判断它"脑中的世界有多完整"。
4. **第三层——技能/插件系统**：有无技能/MCP/插件生态，扩展如何编写与加载，能否修改系统提示词与默认行为，生态成熟度。判断它"可被改造的上限"。
5. **第四层——记忆机制**：有无持久记忆、存在哪里、能否外接或替换记忆源、跨会话一致性。判断它是"长期协作者"还是"一次性问答机"。
6. **分档实测**：按复杂度分三档给真实任务——简单档（单点小改动：显性报错/语法/类型一致性/冒烟）、中等档（跨模块改动：加扫边界/空值/异常路径/依赖/类型安全 + 单测与模块测试）、复杂档（整套项目：加扫并发/超时/性能/安全/全依赖链 + 全量回归与冒烟）。每档独立下发、独立收结果，阶段间强制停顿核对——防止自动化 agent 把多阶段合并偷懒执行。
7. **双通道评价**：机扫通道（可静态发现的技术性问题，agent 能否独立闭环、零人工验码）与人工通道（功能/体验类问题，须真实使用发现）分开结论，互不混淆；机扫通过不等于可用。
8. **输出适配性判断**：
   - 适合干什么活：任务类型 + 难度档位；
   - 与现有工具箱的互补关系：套用轻装/重装框架归位——轻装型（快、适合简单与中低难度任务）、重装型（上下文与工程完备度高、能啃复杂项目但调用重、杀鸡用牛刀）；
   - 接入成本（学习/迁移/维护）与风险（数据外发、稳定性、供应商锁定、行为不可控点）；
   - 一句话分工原则：简单活给轻装，复杂且要求工程质量给重装。

## 坑与红线

- **别只扫一层**：只测了对话或单次编码（第一层）就夸或贬一个工具是最常见错误；记忆与上下文组装往往才是真正差距所在。
- **防偷懒合并**：让自动化 agent "顺手"一次跑完三档实测，等价于没测；必须分档、分阶段、阶段间停顿。
- **机扫 ≠ 人工验收前置**：静态可发现的技术 bug 归机扫通道，功能与体验归真实使用通道，两者结论不得互相顶替。
- 不录入任何账号凭证与密钥；定价与额度只记公开信息。
- 每条结论标注来源（实测/文档/社区反馈）；未经实测的结论必须显式声明。
- 不对目标软件做凭据注入、登录态篡改；改造类实验（改提示词、换记忆源）只在自己有权限的实例上进行。

## 验证方式

- 覆盖检查：报告四层各有独立小节，各附至少一条实测证据或显式"未实测"标注。
- 可复现：换人按同一分档任务清单重测，得出的档位结论一致（允许细节差异）。
- 定位有效：一段时间后回看，该工具实际承接的任务类型是否落在报告预测的档位与分工内。
