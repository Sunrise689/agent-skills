# 软件安全卸载与残留清理

## 何时使用

**触发词**："卸载""清理残留""删干净""safe cleanup""卸载后清理""清目录"。

**适用**：Windows 上卸载可能与其他应用有牵连的软件，并安全清理其残留（含包管理器分发的包、AppX 包、MCP/插件配置引用等）。

**不适用**：只读的系统体检（无删除动作）；用户只要求"重装"而未要求清理。

**前置条件**：对目标机器有管理员权限；已知目标软件的准确名称与安装来源；涉及共享组件或多人共用的机器时，用户已明确授权清理范围。若目标目录归属无法证明（远程环境、路径证据缺失），属于必然失败点——停下先盘点，不得盲删。

## 任务目标

把目标软件从系统里卸干净且不伤及无辜：卸载本身走官方途径；残留只在"归属明确 + 备份校验通过"两个前提同时成立时才定向删除；事后逐项复核系统已干净、相关应用数据完好。

## 操作步骤

1. **盘点**：先列清单再动手——安装包（含包管理器记录）、AppX 包、正在运行的进程、注册的服务、启动项、占用的端口、MCP/插件配置中的引用、用户数据目录。每一项记录"证据 + 归属判断"。
2. **官方卸载**：优先使用该软件自带卸载器或系统"应用与功能"/包管理器官方命令；不绕过卸载器直接删文件。
3. **残留处理**：对确认归属明确、且不被其他应用共享的残留目录/注册项/配置——先压缩备份到安全位置并校验备份可读，再定向删除。删除范围以盘点清单为界，不做清单外"顺手"清理。
4. **逐项复核**：进程已退出、端口已释放、包管理器中已查不到、服务与启动项已移除、残留目录已不存在。
5. **误删确认**：检查与目标软件相关联的其他应用（共享运行时、插件宿主、同类软件）历史数据完好可打开；发现异常立即用第 3 步的备份恢复。
6. **汇报**：输出"盘点清单 → 卸载动作 → 删除明细（含备份位置）→ 复核结果"的对照报告。

## 坑与红线

- **红线**：递归删除前必须能证明目标目录的归属和范围（软件名与路径的对应证据、目录内容抽查）；证明不了就只备份不删除，交用户裁决。
- **红线**：禁止删除归属不明的共享目录（如多个应用共用的运行时/缓存根目录）；拿不准一律视为不明确。
- **红线**：备份未校验（压缩包打不开、内容为空）就执行删除，等同于没有备份。
- **坑**：端口/服务被残留进程占用导致卸载"看起来失败"——先停进程停服务再复核，不要直接改注册表。
- **坑**：MCP/插件配置里对已卸载软件的引用不清理，下次启动会反复报错——盘点阶段就要纳入清单。
- **坑**：用户数据（文档、含个人内容的配置）默认保留，除非用户明确要求删除；它常位于"应用安装目录"之外，别跟着安装残留一起删。

## 验证方式

- 逐项复核输出六项检查结果：进程 / 端口 / 包 / 服务 / 启动项 / 残留目录，全部为"已清除"。
- 备份可恢复演练：从备份压缩包抽验文件可读。
- 关联应用抽查：打开与目标软件同生态的其他应用，历史数据完整可加载。
- 对照盘点清单与删除明细：无清单外删除。
