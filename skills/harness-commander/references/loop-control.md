# 循环收敛控制（Loop Control）

**核心问题**：Agent 最危险的模式不是"做错了"，而是"同一个错误重复做"。循环收敛控制 = 防止 Agent 在死循环里把时间烧光。

## 一、什么是"循环"

以下情况进入循环控制范围：

- 执行某步骤失败，修复后重跑——第 2 轮开始启动收敛检查
- 验证不通过，改代码后重跑验证——第 2 轮开始
- 子 Agent 完成质量不够，重新派活——第 2 轮开始
- 用户说"不对，重做"——第 2 轮开始

任何同一目标的重复尝试都纳入循环控制。

## 二、循环预算

**默认预算：3 轮。** 到达第 4 轮（3 轮尝试后仍未达成目标）→ 立即停止，升级用户。

### 预算消耗规则

- 每一轮尝试（不论成功与否）消耗 1 单位预算
- 更换策略/子 Agent/模型档位仍然算新的一轮（因为目标是同一个）
- 回到上一步重新来算新的一轮

### 例外

以下情况不消耗预算：
- 等待用户回答/确认中的时间不消耗
- 输入问题（用户提供的输入有误）修正后不算新的一轮
- 用户主动说"换个思路"——重置预算为 3

## 三、收敛检查（每轮结束必须执行）

### 三个问题

每轮（从第 2 轮开始）结束时，主指挥必须回答以下三个问题并记录在状态总账中：

**问题 1：这轮比上轮实质前进了多少？**

| 判断 | 含义 |
|---|---|
| 有实质进展 | 原本断掉的依赖链连上了、原本跑不通的测试跑通了、原本找不到的文件找到了 |
| 无实质进展 | 只是换了一种写法、只是改了注释、只是重新格式化 |
| 退步了 | 原本通过的测试现在失败了、原本清晰的结构变混乱了 |

有实质进展才允许进入下一轮。判断标准不是"我做了什么"而是"离目标近了 X%"。

**问题 2：同样的错误是否再次出现？**

同一命令/工具/文件在同一位置报同一个错 → 立即停止（不管还剩多少预算）。

**问题 3：是否在同一位置打转？**

3 轮都在修同一个文件的同一个函数，每次换不同写法但测试结果不变 → 死循环，立即停止。

### 收敛检查输出格式

```text
【收敛检查 | 第 N 轮】

离目标近了: [是/否] — {具体证据，不是感觉}
同样错误重复: [是/否]
同一位置打转: [是/否]

判定结果: [允许下轮 | 停止-无进展 | 停止-死循环 | 升级用户]
```

## 四、死循环判定

满足任意一条即判定为死循环：

| 判定条件 | 示例 |
|---|---|
| 同一位置打转 ≥2 轮 | 反复改同一个函数，每次改法不同但测试结果不变 |
| 同样错误重复 ≥2 次 | `module not found: ./auth` 修了两次还在报 |
| 子 Agent 反复 blocked 在同一个问题上 | 每次都是同一个 question，主指挥回答后还是 block |
| 修复方案在 A 和 B 之间反复横跳 | 这轮用方案 A，下轮方案 A 不行换 B，再下轮 B 不行换回 A |

判定为死循环后：
1. 立即停止所有相关子 Agent
2. 汇总：做了什么、卡在哪、为什么反复失败
3. 写入状态总账 `blockers`
4. 升级用户（带死循环分析摘要）

## 五、循环质量分级

每次任务完成后，给循环质量定级（用于后续沉淀决策）：

| 分级 | 轮次 | 判定 |
|---|---|---|
| **高效收敛** | 1-2 轮达成目标 | 理想状态。无需额外关注 |
| **缓慢收敛** | 3 轮，每轮有实质进展 | 可接受。完成后必须检查"是什么阻碍了快速收敛"并沉淀发现 |
| **死循环** | ≥2 轮打转/错误重复 | 可预防的失败。必须沉淀为规则或自动化检查，防止同类情况再发生 |
| **预算耗尽** | 3 轮用完无进展 | 升级用户后会获得新方向。完成后对比用户建议与原方案，沉淀差异 |

## 六、效率哲学

### 10 人 + 合理流水线 > 100 人 + 混乱加班

不是"多跑几轮总能解决"——多跑几轮 = 成本递增 + 收益递减。收敛控制的价值在于：
- 前面轮的尝试有信息价值（排除了一条死路）
- 后面轮的尝试价值递减（信息已被前几轮消耗）
- 3 轮后边际信息量接近零——该升级了

### 一轮到位 > 十轮空转

最好的循环是不循环。全局优化审视（见 global-optimization.md）的作用就是"在一轮内做对"，而不是"做错了再改"。

### 循环≠坏事

循环本身不是问题。工程就是不断迭代的。有问题的循环是：
- 没学到上一轮的教训（同样错误重犯）
- 没往目标前进一步（只换了表达方式）
- 没意识到该升级了（超过预算还在试）

## 七、与 recovery.md 的联动

| 情况 | 走哪个流程 |
|---|---|
| 单次失败，非循环中 | 走 recovery.md 失败分类+升级链 |
| 同样目标第 2 次尝试 | 启动收敛检查（本章） |
| 收敛检查判定"允许下轮"但执行中再失败 | 走 recovery.md 分类，但也计入当前轮次 |
| 死循环判定 | 走本章停止流程，汇总后升级用户 |

> **一句话原则**：执行前审视一遍到位 > 执行后纠错重来；纠错时有实质进展才继续 > 同一位置打转立刻停。节省的不只是时间，是目标的确定性。
