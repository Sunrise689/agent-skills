# 安全护栏（Guardrails）

**核心原则**：复杂的自动执行系统必须有硬护栏。护栏不是"建议"而是"拦截器"——触发即停，不商量。

## 一、黑名单拦截

### 规则

以下命令/操作必须人工确认后才能执行。Agent 可提出方案，但不可自行执行：

| 操作类别 | 具体命令 | 风险 |
|---|---|---|
| 递归强制删除 | `rm -rf`、`rm -r --force`（含非项目路径） | 不可逆数据丢失 |
| Git 强制推送 | `git push --force`、`git push -f`、`git push --force-with-lease` | 覆盖远程历史 |
| 删库/删表 | `DROP DATABASE/TABLE`、`DELETE FROM ...` 无 WHERE、`TRUNCATE` | 不可逆数据丢失 |
| 批量文件覆盖 | `cp -r` 覆盖非空目录、`mv` 覆盖已有文件（非项目工作区） | 静默丢失原数据 |
| 发送到外部 | `curl POST`/`scp`/`rsync` 向非项目服务器发送数据 | 数据泄漏 |
| 修改系统配置 | `/etc/*`、chmod 777、`chown`（非当前用户文件） | 系统级安全 |
| 环境变量修改 | 修改 `.bashrc`/`.zshrc`/`.profile` 中非项目相关变量 | 影响宿主机 |
| 未加密密钥外传 | 任何含 `SECRET`/`TOKEN`/`KEY` 的环境变量打印到日志或文件 | 密钥泄漏 |

### 示例

```
✅ 允许：rm ./node_modules/.cache/temp.txt
❌ 拦截：rm -rf /usr/local/lib/*
处理：停止执行，输出「需人工确认: rm -rf /usr/local/lib/*」
```

### 处理方式

触发黑名单后：
1. **立即停止**当前操作
2. 输出：`需人工确认: {具体操作命令与风险说明}`
3. 等待用户回复"确认"/"允许"后方可继续
4. 不提供"假设已经确认"的任何替代方案

## 二、范围检查护栏

### 规则

**只做用户明确要求的，不“顺手”做额外改动。** Agent 常有"这个地方也应该改一下"的冲动——这正是护栏要阻截的。

| 行为 | 判定 | 示例 |
|---|---|---|
| 用户说改 A，Agent 顺手改 B | **超范围** | 用户说"修复 login 页面的按钮样式"，Agent 顺手改了注册页样式 → 拦截 |
| 用户说搜索 X，Agent 搜索后顺手分析了结构 | **轻微超范围** | 警告但可不拦截（分析无副作用） |
| 用户说"优化性能"，Agent 重构了不相关的模块 | **严重超范围** | 拦截，要求补充需求 |
| 修复一个 bug 时发现另一个 bug，Agent 顺手修了 | **超范围（且危险）** | 拦截。分析可作为建议提出，但不可直接修改 |

### 处理方式

触发范围检查后：
1. **暂停**当前操作
2. 输出：`检测到超范围变更: {变更内容}。原需求未覆盖此项，是否纳入范围？`
3. 等待用户确认（"是"/"纳入"/"只做原需求"）
4. 不允许以"这样做更好"为理由跳过确认

### 不触发的情况

- 修改 bug 连带修改引用了同一函数的其他文件（已在原范围内）
- 搜索时读取邻近文件以理解上下文（只读无副作用）
- 测试运行时自然覆盖到的相关代码路径

## 三、歧义拒绝护栏

### 规则

**指令有两种以上合理解读时，不选一种就执行——先问清楚。**

| 歧义类型 | 示例 | 处理 |
|---|---|---|
| 目标歧义 | "清理一下"——是清理日志？清理缓存？清理未使用代码？ | 列出 2-3 种最可能的含义，让用户选 |
| 范围歧义 | "修 bug"——哪个 bug？什么表现才算修好？ | 要求用户补充 bug 描述或验收条件 |
| 对象歧义 | "替换那个组件"——那个是哪个？路径？文件名？ | 要求用户明确指定文件路径或组件名 |
| 方案歧义 | "优化"——是性能优化？可读性优化？架构优化？ | 要求用户明确优化目标和可接受的代价 |

### 不触发的情况

- 歧义只有一个合理选项（上下文已排除了其他含义）
- 歧义不影响执行路径（两个解读产生相同动作）
- 用户使用了明确的文件名/路径/命令

### 处理方式

1. 不执行
2. 输出：`指令存在歧义，以下解读可能：
   - A. {解读A}
   - B. {解读B}
   请明确选择。`
3. 等待用户明确后再执行

## 四、护栏联动

| 场景 | 护栏 |
|---|---|
| 执行任何写操作前 | 先过黑名单检查 |
| 修改文件范围超出用户指定时 | 先过范围检查 |
| 用户指令可多解时 | 先过歧义拒绝 |
| 子 Agent 产出越界操作建议时 | 主指挥过范围检查后再决定是否采纳 |

> **护栏的总原则**：不确定就停。停一下比做错再回滚便宜一百倍。
