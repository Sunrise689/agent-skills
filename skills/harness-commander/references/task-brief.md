# 固定任务简报模板（Task Brief）

**核心问题**：口头派活容易漏约束、漏验收、漏上下文。子 Agent 理解偏差源于指令表达不完整。标准化简报 = 可复现的派活。

## 一、简报模板

```text
【任务简报】

任务ID:     {task_id}
模型档位:   {Tier 0|1|2|3}

## 1. 目标（一句话）
{一句话描述这个子任务要达成什么}

## 2. 验收标准
- 完成判据: {明确、可验证的完成条件}
- 不合格判据: {什么情况算失败，停止并返回}

## 3. 输入材料
- 文件/数据源: {具体路径}
- 上下文简述: {只给必要背景，不传主对话历史}
- 注意: {特殊的已知约束}

## 4. 操作约束
- 允许: {列举允许做的操作}
- 禁止: {列举明确禁止的操作}

## 5. 产出格式
- 格式: {JSON/Markdown/文本}
- 必须包含: {字段清单}
- 落盘位置: {写入 .harness/artifacts/{run_id}-output.md}

## 6. 状态汇报
- 状态文件路径: .harness/workers/{run_id}.json
- 心跳间隔: 每步骤完成或≤3分钟更新一次
- 超时时间: {默认600秒}
- 遇到需决策的问题: 写入状态文件 question 字段，不猜测

## 7. 完成报告
- 只报结果，不直播过程
- 报告格式: 结果摘要（≤5行）+ 产出物路径 + 证据等级自评 + 残余风险
```

## 二、填写规范

### 2.1 目标

必须是一句话，不能是段落。"分析 AUTH 模块"不行，太模糊。"找出 AUTH 模块中所有 Session 相关代码调用点，列出文件路径和行号"——这才合格。

### 2.2 验收标准

必须是**可验证的**（能写成自动化断言的标准）。
- ✅ "找到 ≥3 个 Session 调用点，包含文件路径+行号+调用上下文"
- ❌ "找到所有相关代码"
- ✅ "lint 结果 error 数 ≤ 当前 error 数"
- ❌ "改善代码质量"

### 2.3 操作约束

**禁止项比允许项更重要**。宁可写多了约束，不可让子 Agent 自由发挥。
- ✅ 明确写出 `❌ 不允许修改任何文件`
- ✅ 明确写出 `❌ 不允许安装新依赖`
- ✅ 明确写出 `❌ 不允许调用外部 API`

### 2.4 产出格式

越具体越好。不写"返回结果"，写：
```text
格式: Markdown
必须包含:
  - 文件清单（路径列表）
  - 每个文件的关键发现（≤3行/文件）
  - 总体摘要（≤5行）
```

## 三、示例

```text
【任务简报】

任务ID:     harness-20260809-t001-search-auth
模型档位:   Tier 1

## 1. 目标
找出仓库中所有与 Session 认证相关的代码文件、配置和调用点，包括文件路径、行号、Session 相关代码片段。

## 2. 验收标准
- 完成判据: 至少发现 3 个相关文件，每个文件有路径+行号+代码片段
- 不合格判据: 搜索工具不可用、仓库结构无法识别、0 结果

## 3. 输入材料
- 文件/数据源: 仓库根目录 /app
- 上下文简述: 项目包含 Express + JWT 两种认证，目标是从 Session 迁到 JWT，现需定位 Session 代码
- 注意: 区分"使用了 Session"和"定义了 Session 类型"，只报告实际调用点

## 4. 操作约束
- 允许: 搜索（grep/glob）、读取文件内容、统计行数
- 禁止: ❌ 修改任何文件；❌ 安装依赖；❌ 执行代码

## 5. 产出格式
- 格式: Markdown
- 必须包含:
  - 搜索结果摘要（总文件数、候选调用点数）
  - 每个文件的路径、行号、代码片段（≤3行上下文）
  - Session 使用类型分类（路由/中间件/工具函数/配置）
- 落盘位置: .harness/artifacts/t001-search-auth-output.md

## 6. 状态汇报
- 状态文件路径: .harness/workers/t001-search-auth.json
- 心跳间隔: 每步骤完成或≤3分钟更新一次
- 超时时间: 600秒
- 遇到需决策的问题: 写入状态文件 question 字段，不猜测

## 7. 完成报告
- 只报结果，不直播过程
- 报告格式: 结果摘要（≤5行）+ 产出物路径 + 证据等级自评 + 残余风险
```

## 四、完成报告格式

子 Agent 完成后返回的最终消息结构：

```
【完成报告】
任务ID: {task_id}
状态: done|error

## 结果摘要
{≤5行的关键结果}

## 产出物
{产出物路径及简要说明}

## 证据等级自评
{Present|Wired|Exercised|Outcome|Insufficient} — {一句话理由}

## 残余风险
{哪些不确定/未验证——不写"无"，总有不确定的地方}
```

> **一句话原则**：简报写得越具体，子 Agent 跑得越稳。模糊指令 = 模糊结果。
