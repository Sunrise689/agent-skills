# 证据状态分级详解（Evidence States）

**核心铁律：配置了 ≠ 使用了。** 任何结论的置信度，取决于支撑它的证据走到了哪一档。

## 一、四档定义与判定方法

| 等级 | 含义 | 英文 | 判定方法 | 得分上限 |
|---|---|---|---|---|
| **存在** | 配置/文件/证据存在于系统文件系统或仓库中 | Present | `ls` 可见、路径存在、配置项存在、import 语句存在 | **74** |
| **已连接** | 该证据已被连接到明确的执行路径 | Wired | 调用链中存在引用、有触发点（hook/gate/script target）、有路由指向 | **84** |
| **已运行** | 在真实或模拟环境中被实际执行过 | Exercised | 有运行日志产出、有测试通过/失败记录、有执行 trace | **94** |
| **结果可证** | 执行结果数据与结论一一对应，无歧义 | Outcome | 结果值与结论吻合、测试断言覆盖结论路径、指标数据直接支撑 | **100** |
| **缺失** | 无任何可观察证据 | Missing | 找不到任何痕迹、关键值为 null/undefined/placeholder | **59（封顶）** |

### 逐级详解

**Present (74) — "它在那儿"**
- 可判：文件存在于仓库、`package.json` 中有某个依赖声明、`import` 语句写在源文件里
- 不可判：该配置被加载、该依赖在运行时被调用、该引用路径能正常工作
- 误判高发区：看到 README 写"支持 XX"→ 只能 Present，文档写得好不代表功能可用

**Wired (84) — "它连着"**
- 可判：`tsconfig.json` 的 `include` 包含该文件路径、脚本命令指向该文件、CI pipeline 引用了该步骤、git hook 注册了该检查
- 不可判：该连接在真实执行时被触发、连接路径没有断点/死链
- 提升关键：找到从声明到执行入口的完整引用链（声明 → 入口配置 → 触发点）

**Exercised (94) — "它跑过"**
- 可判：有运行日志、有测试结果输出、CLI 有 stdout/stderr、CI job 有执行记录
- 不可判：日志是样板/骨架而非真实输出、测试结果与预期完全一致但测试本身不覆盖目标路径
- 提升关键：日志内容与预期行为一致，且日志产出时间是近期/当前会话内

**Outcome (100) — "它证明"**
- 可判：运行结果值直接匹配结论断言、测试覆盖率报告显示目标路径被命中、指标数值与结论推算一致
- 不可判：推论链条中有任何推测环节（"应该是""通常意味着""大概率"）
- 必要条件：证据 → 结论之间没有推断跳步

**Missing (59 封顶) — "没证据"**
- 封顶 59 分的设计意图：即使其他维度满分，缺一条关键证据就拉低到"不可交付"等级
- 禁止行为：不可用同仓库其他路径的证据来"替代推测"缺失的关键证据

## 二、常见误判速查

| 看到的 | 能判 | 不能判 |
|---|---|---|
| 配置文件 `.eslintrc.js` | Present | 已生效、规则被遵循 |
| `package.json` 中 `"lint": "eslint src/"` | Wired | lint 真正执行过、ESLint 报错被修复 |
| 有 lint 执行日志 | Exercised | 修复结果正确、团队已全部遵循 |
| README 写"使用 TypeScript 严格模式" | Present | `strict: true` 真的在 `tsconfig` 中且被 tsc 读取 |
| `import X from './module'` | Present | X 在当前运行时路径中真的被调用 |
| Skill 目录存在 `SKILL.md` | Present | Skill 被正确安装、被触发过、触发后效果合格 |
| git hook 目录存在 `pre-commit` | Wired | hook 在执行 `git commit` 时真的跑了 |
| CI yaml 包含 test job | Wired | job 最近一次执行通过了、通过结果与代码质量正相关 |

## 三、应用场景

### 3.1 任务验收
不能只看文件生成了（Present），要确认至少跑过一次（Exercised）。交付前必须满足：所有核心断言 ≥ Wired，关键断言 ≥ Exercised。

### 3.2 多源对账（Reconciliation）
子 Agent 返回候选发现时，先按证据等级分别标注，再主分析器对账。同目标+同后果+同修复路径的候选项用最高等级合并；等级不同的保留各版本并标注等级差异。

### 3.3 误报防火墙联动
当一条发现依赖的关键证据等级为 Present 或 Missing 时，该发现进入"证据不足"队列，不可赋 severity ≥ Medium。必须升级到 Wired 以上才能进入正式发现列表。

### 3.4 循环工程决策
Loop Discovery 10 问中，第 3-10 问每条都对应一个证据等级要求：
- 第 3 问（输入稳定可获取）→ 至少 Wired
- 第 4 问（流程可复现）→ 至少 Wired
- 第 5 问（客观验证方式）→ 至少 Exercised
- 第 8 问（输入输出契约明确）→ 至少 Wired
- 第 10 问（评估指标）→ 至少 Wired

任意一条不满足对应等级要求，即不算 YES。

### 3.5 V2 Pro 联动

- **状态总账**：每个子任务完成时，必须在 `HARNESS_STATE.json` 中记录 `evidence_level`。总账中所有低于 Wired 的子任务自动标记为"置信度不足"，交付前需升级或声明残余风险。
- **循环收敛控制**：每轮收敛检查中，"离目标近了"的判断依赖证据等级提升。Present→Wired = 前进了一档；Present→Present（原地） = 无实质进展。如果三轮证据等级无变化 → 判定为无进展，触发升级。
- **失败分类**：证据不足导致的失败归类为"输入问题"（输入信息不足以支撑结论），而非"模型问题"，走输入问题升级链。

> **一句话原则**：有证据才下结论，证据等级决定结论上限。
