# 桌面坐标库三件套

## 技能定位（必读）

本技能交付的是一套**方法**：UIA 建库 → 按名点击 → 锚点兜底的"建库-执行"流程，即 scanner / executor / anchor 三件套的建库与使用规范。**坐标库必须由使用者在自己的机器上现场生成**——每台机器的桌面布局、分辨率、DPI、窗口位置都不同，本技能绝不随包附带任何坐标数据、锚点截图或预生成 JSON 库；对任何来历不明的坐标库不得直接执行，一律按本方法重新扫描建库。

## 何时使用

**触发词**："桌面坐标库""UIA 建库""按名点击""锚点校验""桌面应用自动化点击""scanner/executor/anchor"。

**适用**：对界面相对稳定的桌面应用做可重复的点击自动化，即"模型探索一次、脚本执行一辈子"的场景。

**不适用**：网页自动化（走浏览器协议）；无窗口的纯命令行任务；界面频繁随机变化、无稳定锚点的场景。

**前置条件**：Windows 环境（实测以 Win11 为准）；可运行 Python（pyautogui、Pillow、numpy）；PowerShell/.NET UIAutomation 可用；目标应用窗口能被无障碍树（UIA）识别——自绘控件读不到时用 `--add-manual` 人工补录兜底。

## 任务目标

建立"控件名 → 相对坐标 + 锚点截图"的 JSON 坐标库；此后脚本按名字找控件、换算绝对坐标点击；每次点击前用锚点图校验界面未变，变了就拒绝点击并标记重扫。目标：**点击可复现，误点可拦截**。

## 操作步骤

1. **扫描建库（scanner）**：运行 scanner 脚本，用 PowerShell/.NET UIAutomation 读目标窗口的无障碍树，取每个控件的名称与中心点（进程先 `SetProcessDPIAware`，统一物理像素），生成 JSON 库。字段包含：应用名、窗口标题指纹、窗口矩形、元素列表（名称、相对坐标、锚点截图、来源、扫描时间）。UIA 读不到的自绘控件用 `--add-manual` 人工录点补入。
2. **执行点击（executor）**：按窗口标题指纹找窗 → 激活窗口（最小化则先还原，见坑 1）→ 用"控件相对坐标 + 窗口当前矩形"换算绝对坐标 → 先过锚点校验 → 通过才用 pyautogui 点击 → 写日志。
3. **锚点兜底（anchor）**：用 FFT 归一化互相关（NCC，Pillow+numpy 实现，阈值 0.80）对比当前界面与建库时的锚点截图。**分数不达标即判定界面已变：把该条目标记为"需重扫"，绝不乱点**；重新执行第 1 步更新库后再继续。
4. **验收**：每次点击前后截图对比，用 numpy 统计像素差异数；对窗口做一次移动 (dx,dy) 后复测，验证 abs_new = abs_old + (dx,dy) 且锚点分数不下降，坐标库才算合格。

## 坑与红线（Win11 实测）

- **最小化窗口的矩形是假的**：GetWindowRect 对最小化窗口返回 (-32000,-32000)。扫描或移动前必须 IsIconic 判断 → ShowWindow(9) 还原 → SetForegroundWindow 激活，再取坐标。
- **合成鼠标拖动会被吞**：pyautogui 的 mouseDown + 渐近 moveTo + mouseUp 组合去拖标题栏，常出现位移 (0,0) 无效果。改用 Win32 `MoveWindow` 直接设置窗口矩形等效替代。
- **多标签应用恢复会话会翻出用户历史文档**：恢复会话类应用会自动重开用户之前的文档。测试窗口的标题指纹必须带专用文件名防混淆；**对含用户文档的窗口永不发 Ctrl+W、Ctrl+Shift+T 一类按键**；动任何用户进程前先向用户确认。
- **高 DPI 屏**：DPI 缩放（如 200%）下逻辑坐标与物理坐标不一致，全流程统一使用物理像素。
- **PowerShell 输出乱码**：输出流加 UTF-8 前缀，避免中文控件名读成乱码。
- **红线**：锚点校验失败仍强行点击；直接执行来历不明的坐标库；未经确认对含用户文档的窗口发送危险按键——三条均禁止。

## 验证方式

- 用一个专用测试窗口（文件名唯一、与用户文档隔离）完整走通建库 → 点击 → 锚点校验，日志显示点击成功。
- 移动窗口后复测：绝对坐标按 (dx,dy) 平移，锚点分数不低于原值。
- 人为改变界面（切标签、改内容）后重跑 executor：应被锚点拦截并标记"需重扫"，而不是误点。
- 检查产物 JSON：不含任何真实个人文档路径或用户数据样本。
