# 确定性数值建模五层流水线

## 何时使用

- 触发词与场景："XX 到底值不值""A 和 B 哪个划算""这个配置该不该换""资源该投到哪"——凡是能拿到确定数据、结论可以被复算的选择题。
- 适用：确定性封闭系统（数据固定、无随机数或实验可重复）中的数值比较问题：产品/配置项选型、资源投放、参数权衡、回测类决策。判定特征：固定输入 → 固定输出。
- 不适用：开放随机系统（无法取得稳定数据的舆论、人际、一次性行情）；数据层拿不到的黑箱也不要硬建模。
- 前置条件：至少一种可靠数据来源 + 一种实测校准途径。执行环境若取不到数据，本技能只输出"数据缺口清单"，不出结论。

## 任务目标

把直觉之争转成一条可复算的五层流水线，最终输出 if-then 规则与临界值，而非单一答案；并交付两档结果——"遇到什么场景选什么"的速查表，以及随场景参数实时演进的动态路线。

## 操作步骤

1. **数据层**：多来源按可靠度排队——官方接口/文档 > 官方页面 > 第三方整理的公开数据 > 本地实测真值（最终以实测为准）。逐条标注版本号与出处，禁止混用不同版本的数据。
2. **结算引擎**：把官方/既定的乘区结算链一次实现、一次写对：收益 = 基础值 × 系数 → 各修正项 → 乘区与加区按规则复合 → 最终结果。引擎通用，换对象只换参数表，不重写公式。
3. **场景参数**：己方参数 × 对象/环境参数 × 时间占比（某状态覆盖的时间比例、某行为占比、资源节点）。没有场景参数的比较都是假比较。
4. **比较器（四把尺子）**：
   - 边际增量：每单位成本的收益增量（统一货币口径，如每元等效增益）；便宜本身就是属性；
   - 作用面加权：等效增益 = 名义增益% × 该增益覆盖的收益占比（隐藏变量，见红线）；
   - 交叉点反解：令两个选项收益相等，反解出临界参数值 → 直接生成 if-then 规则；
   - 期望折算：条件增益 = 增益倍率 × 条件发生的时间/概率占比。
5. **校准闭环**：实测 → 修正假设参数 → 重算 → 收敛。验收顺序从常数（单个公式系数）到单项（单个配置项）到整轮（完整流程）。
6. **输出两档**：速查表版（按典型场景参数预计算好"遇什么选什么"）与实时精调版（按当前参数现场重算分支）；两档共用同一套底层数学，前者是后者在典型参数上的预计算。
7. **预判层（可选）**：对手/环境可预测时，其公开选择即信息——逐次观察逐步收窄其参数分布（贝叶斯式更新），提前把自己的配置顺序调向克制路线，而非推倒重来。

## 坑与红线

- **作用面是隐藏变量**：增益%必须乘"它覆盖的收益占比"。某增益只作用于部分收益渠道时，按全额名义值比较是幻觉——这是最多直觉反转的来源。
- **乘区相乘、同区相加**：资源应投给当前边际最小的乘区，而不是堆死在单个乘区里。
- **固定值前期薄利，复利前期常胜**：固定值增益在总量小时占比甚微；滚雪球型收益（成长/经济类）前期往往更优——前期决策优先复利项。
- **全民常识可被数字反转**：凡"大家都这么说"的结论都要过一遍流水线。没人算过的黑箱领域 = 超额收益区。
- 不要用标签（"这是进攻项/防御项"）代替数字；不同性质的收益必须折算到同一目标函数再比。
- 只在同一版本数据内计算；跨版本混数即污染。
- **元逻辑**：超额收益 = 方法成熟度 × 场景渗透率的错位。同一方法在成熟领域不值钱，在没人算过的场景是降维打击；错位常是"想不到用"（联想缺口）而非"不会算"（能力缺口）。把成熟方法带进渗透率低的领域，是成本最低的非共识。

## 验证方式

- 复算验证：第三者只拿参数表 + 引擎，能独立复现你的全部数字结论。
- 校准验证：常数级 → 单项级 → 整轮级逐层与实测对账，误差收敛并记录残差。
- 反转验证：至少给出一条"直觉与计算相反"的结论及其交叉点数值；一条都找不出来，通常说明比较器没算透。
- 规则验证：每条 if-then 规则都能指出它反解自哪个交叉点、基于哪一版数据。
